# 面试讲解提纲

## 30 秒项目介绍

“我基于 Raspberry Pi 500+ 做了一个嵌入式 Linux 控制中心。程序通过 SPI 驱动 ST7789 小屏幕，通过 GPIO 读取按键和摇杆，通过网络接口获取 Codex 用量，同时控制键盘 RGB 灯和外接显示器。C 学习版采用 epoll 事件循环，把硬件驱动、状态机和 UI 渲染分层。”

## 为什么它属于嵌入式 Linux

- 运行在资源受限、面向硬件控制的 Raspberry Pi 上。
- 直接使用 SPI、GPIO、I²C/DDC、蓝牙 HID 等接口。
- 但运行在完整 Linux 上，不是 MCU 裸机或 RTOS 固件。

## 为什么使用 epoll

- GPIO 事件文件描述符和 `timerfd` 都能放进同一个事件循环。
- 不需要为每个按键创建轮询线程。
- 系统空闲时不消耗 CPU，按键响应也比固定间隔轮询稳定。

## 状态机怎么设计

Codex 状态优先级为：

```text
需要确认 > 正在处理 > 刚完成（60 秒） > 闲置
```

键盘模式灯只在“Codex 闲置且键盘模式开启”时接管。其他时候始终显示 Codex 状态灯。这避免了多个布尔变量互相覆盖造成的状态混乱。

## 网络规则

- `getifaddrs` 先检查物理 Wi‑Fi/有线网卡是否有 IPv4。
- 没有物理地址：显示 `IP: --` 和红点。
- 有地址后再执行 `ping baidu.com`。
- 连续两次失败才判定断网，避免偶发丢包让 UI 闪烁。
- 网络异常时保留最后一次有效额度，并通过红点和更新时间表示数据可能过期。

## 如何避免按键误触

- 使用 GPIO 双边沿事件记录按下和松开。
- 松开时才触发短按动作。
- 按住达到阈值后触发长按，并设置 `long_fired` 防止重复执行。
- 服务启动后必须先观察到稳定松开，才允许识别长按，避免 GPIO 初始化抖动重启桌面。

## Python 与 C 的取舍

- Python 开发快、UI 和系统集成方便，适合快速迭代。
- C 对内存、时延和硬件访问控制更明确，适合学习底层机制。
- 生产中可以保留 Python 桌面 UI，把按键、SPI 和状态机下沉到 C 守护进程，通过 Unix Socket 通信。

## 可以继续扩展的方向

- 用 cJSON/json-c 增量解析多个 Codex JSONL 会话。
- 使用双缓冲减少 LCD 撕裂。
- 将 GPIO 和 SPI 封装成可注入接口，给状态机编写单元测试。
- 用 Unix Socket 将 C 守护进程与 GTK 控制中心解耦。
